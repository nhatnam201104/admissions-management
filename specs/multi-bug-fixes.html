Multi Bug Fixes — Aspiration Validation, Age, NK Scores, Talent Subject Mapping

Intent

Khắc phục bốn bug làm dữ liệu tuyển sinh không nhất quán và logic tính điểm sai cho ngành năng khiếu: (1) thí sinh đăng ký trùng nguyện vọng cùng ngành/cùng phương thức/cùng tổ hợp, (2) độ tuổi tối thiểu đang cho phép 15 tuổi (UEF yêu cầu ≥17), (3) điểm năng khiếu (NK1/NK2) đang đặt sai chỗ ở phương thức ĐGNL trong khi nghiệp vụ thuộc THPT, (4) tổ hợp xét tuyển có môn năng khiếu (HAT, VE, TIENG_DUC...) không map được sang cột nk1/nk2 trong điểm thí sinh — mọi NV ngành năng khiếu hiện đều thiếu điểm.

Decisions

Bug 1 — Định nghĩa "trùng nguyện vọng"

  • Trùng = cùng nn_cccd + cùng nv_manganh + cùng tt_phuongthuc + cùng tt_thm (tổ hợp).
  • Lưu ý: nv_tt (số thứ tự NV 1–5) không tham gia định nghĩa trùng — vì nếu cùng ngành/phương thức/tổ hợp mà chỉ khác số thứ tự thì vẫn là trùng về bản chất nghiệp vụ. Số thứ tự đã có check riêng (existing logic giữ nguyên).
  • Cho phép thí sinh đăng ký cùng ngành nhưng khác phương thức (THPT/ĐGNL/VSAT) hoặc khác tổ hợp — đây là pattern hợp lệ trong tuyển sinh UEF.
  • Áp dụng cả cho create và update (tránh cập nhật làm trùng với NV khác của chính thí sinh đó).
  • Không làm trùng với chính NV đang sửa (loại trừ id hiện tại qua tham số excludeId).

Bug 2 — Tuổi tối thiểu

  • Đổi age < 15 → age < 17 tại CandidateFormDialog.
  • Đồng bộ thông báo lỗi.
  • Thêm validate cùng quy tắc tại CandidateServiceImpl.normalizeAndValidate() để bảo vệ luồng import (Bean Validation chỉ có @Past hiện tại không đủ).

Bug 3 — Dời NK từ ĐGNL sang THPT

  • NK1/NK2 thuộc createThptPanel(), bỏ khỏi createDgnlPanel().
  • Khi method = THPT thì lưu NK1/NK2; khi method = DGNL thì setNk1/Nk2(null) (clear, không validate).
  • Validation range NK ở ScoreFormDialog.validateForm() và ScoreServiceImpl.validateScoreRangeByMethod() chuyển sang nhánh THPT.
  • Thang điểm NK ở THPT là 0–10 (đồng nhất với các môn THPT khác). Bỏ thang 0–100 cũ ở DGNL — đó là số sai do nghiệp vụ NK không thuộc ĐGNL ngay từ đầu.
  • Cập nhật rõ ScoreServiceImpl.validateScoreRangeByMethod(): nhánh DGNL bỏ validate NK1/NK2; nhánh THPT thêm validateRange("NK1", dto.getNk1(), 0, THPT_MAX_SCORE) và NK2 (THPT_MAX_SCORE = 10).
  • Schema DB không đổi: cột nk1/nk2 trong xt_diemthixettuyen đã tồn tại độc lập phương thức.
  • Preview tab cập nhật: NK1/NK2 hiển thị trong nhóm "Điểm các môn THPT", không phải nhóm "Điểm ĐGNL".

Bug 4 — Map môn năng khiếu vào nk1/nk2 theo vị trí

  • Map theo vị trí trong tổ hợp: môn năng khiếu đầu tiên gặp trong th_mon1/2/3 → nk1, môn thứ hai → nk2.
  • Định nghĩa "môn năng khiếu" = mã môn không thuộc tập môn văn hóa/ngoại ngữ/ĐGNL chuẩn (TO, LI/LY, HO/HH, SI/SH, SU/LS, DI/DL, VA/NV, AN/N1, NL1, NK1, NK2). Bất kỳ mã khác (HAT, VE, TIENGDUC, NHAC, MUA, KICH, ...) được coi là môn năng khiếu.
  • Không thay đổi schema DB, không thêm cột metadata.
  • Refactor getScoreField(score, monCode) → getScoreField(score, tohop, slotIndex) để biết slot trong tổ hợp khi map NK theo vị trí.
  • Một tổ hợp tối đa 2 môn năng khiếu (giới hạn vật lý của nk1/nk2); nếu vượt → log warn và return null cho slot dư.
  • SubjectGroupFormDialog.DEFAULT_SUBJECTS bổ sung các môn năng khiếu phổ biến để giảm phải tự nhập.
  • Phụ thuộc Bug 3: Bug 4 chỉ đúng khi NK1/NK2 đã được nhập ở phương thức THPT (sau Bug 3). Tổ hợp năng khiếu hiện tại chỉ thuộc phương thức THPT trong nghiệp vụ UEF — VSAT/ĐGNL không có ngành năng khiếu nên không cần xử lý 2 phương thức kia.
  • VSAT scale safety: trong nhánh VSAT, môn năng khiếu (nếu có do data import sai) sẽ bypass convertScoreVsat() để tránh quy đổi sai thang (NK trên thang 10, VSAT trên thang 150). Cụ thể: calculateForTohopVsat chỉ convert các môn không phải năng khiếu; với slot năng khiếu, dùng raw value làm convertedValue luôn (giống THPT identity).

Approach

Mỗi bug được fix tại tầng phù hợp — UI cho user input, service cho luồng import/server-side. Bug 1 thêm query existsByCccdAndManganhAndPhuongthucAndThm trong repository và gọi từ cả AspirationFormDialog.save() lẫn AspirationImportHelper.saveAspirationRow() để bảo vệ cả 2 đường ghi. Bug 2 chỉnh hằng số tuổi và đồng bộ validate sang service. Bug 3 thuần UI/validation: di chuyển field NK, đổi nhánh save/validate, không động tới schema. Bug 4 thay vì hardcode 8 môn, ta nhận diện môn năng khiếu bằng negation (không nằm trong tập chuẩn) và map theo thứ tự xuất hiện trong tổ hợp — giải pháp này không yêu cầu migration và xử lý được mọi môn năng khiếu mới mà UEF có thể thêm.

    "TO", "LI", "LY", "HO", "HH", "SI", "SH",

private static boolean isTalentSubject(String code) {
    if (code == null) return false;
    return !STANDARD_SUBJECTS.contains(code.trim().toUpperCase());

Refactor signature getScoreField: cần biết tổ hợp + vị trí slot để map NK theo vị trí. Dùng resolver tách riêng:

private Double resolveScoreForSlot(XtDiemthixettuyen score, XtNganhTohop tohop, int slotIndex) {
    String code = switch (slotIndex) {
        case 1 -> tohop.getThMon1();
        case 2 -> tohop.getThMon2();
        case 3 -> tohop.getThMon3();
        default -> null;
    };
    if (code == null) return null;

    // Nếu là môn năng khiếu → map theo vị trí xuất hiện trong tổ hợp.
    if (isTalentSubject(code)) {
        int talentRank = computeTalentRank(tohop, slotIndex);
        return switch (talentRank) {
            case 1 -> score.getNk1();
            case 2 -> score.getNk2();
            default -> {
                log.warn("Tổ hợp {} có quá 2 môn năng khiếu (slot {}={}), bỏ qua",
                        tohop.getMatohop(), slotIndex, code);
                yield null;
            }
        };
    }
    return getScoreField(score, code);
}

/** Đếm slot năng khiếu đứng trước (kể cả slot hiện tại) → trả về thứ hạng 1, 2, 3... */
private int computeTalentRank(XtNganhTohop tohop, int currentSlot) {
    int rank = 0;
    for (int i = 1; i <= currentSlot; i++) {
        String c = switch (i) {
            case 1 -> tohop.getThMon1();
            case 2 -> tohop.getThMon2();
            case 3 -> tohop.getThMon3();
            default -> null;
        };
        if (isTalentSubject(c)) rank++;
    }
    return rank;
}
